# Elegant Objects - Object-Oriented Design Patterns

## EOO.1.3 - Keep constructors code-free

**Type:** Applied design pattern  
**Status:** Source-derived  
**Normativity:** Informative

### EOO.1.3:1 - Problem frame

Construction composes an object; using it performs work through its public contract.

### EOO.1.3:2 - Problem

Parsing, I/O, validation with side effects, or other work in a constructor makes instantiation execute behavior before a client has requested it.

### EOO.1.3:3 - Forces

- Eager computation can simplify a field type and may appear faster.
- Deferred computation preserves control for the client and avoids unnecessary work.

### EOO.1.3:4 - Solution

Have constructors assign supplied objects or compose small collaborators; do not ask arguments to work. Encapsulate a deferred adapter such as `StringAsInteger` rather than parse in `Cash(String)`.

#### EOO.1.3:4.1 - Bad vs. good Java examples

**Bad**

```java
final class Cash {
    private final int cents;

    Cash(String text) {
        this.cents = Integer.parseInt(text);
    }
}
```

**Good**

```java
final class Cash {
    private final Number cents;

    Cash(Number cents) {
        this.cents = cents;
    }

    int cents() {
        return cents.intValue();
    }
}

final class TextNumber extends Number {
    private final String text;

    TextNumber(String text) {
        this.text = text;
    }

    public int intValue() {
        return Integer.parseInt(text);
    }

    public long longValue() { return intValue(); }
    public float floatValue() { return intValue(); }
    public double doubleValue() { return intValue(); }
}
```

### EOO.1.3:5 - Archetypal Grounding

**System:** `Cash` stores a `Number` constructed from text and requests `intValue()` only when its contract needs a number.  
**Episteme:** a constructor records composition, whereas a method invocation is evidence of requested run-time work.

### EOO.1.3:6 - Bias-Annotation

This favors **Onto/Epist** and **Prag** lenses by separating object formation from execution. It discounts cases where a language or resource contract requires eager validation.

### EOO.1.3:7 - Conformance Checklist

- Constructors only assign or compose collaborators.
- No constructor performs I/O or invokes operational methods on arguments.
- Deferred computation remains explicit in a named collaborator.

### EOO.1.3:8 - Common Anti-Patterns and How to Avoid Them

- **Eager parsing:** wrap the source value in a conversion object.
- **Hidden network/file access:** move it behind a requested capability.

### EOO.1.3:9 - Consequences

Construction becomes predictable and clients retain control over when work occurs. The design may require more small classes and deliberate caching where repeated computation is costly.

### EOO.1.3:10 - Rationale

The pattern applies the FPF distinction between a design-time composition and a run-time occurrence: creating an object is not yet evidence that its work was requested.
